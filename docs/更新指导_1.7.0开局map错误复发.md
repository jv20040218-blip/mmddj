# 更新指导：1.7.0 开局 map 错误复发

日期：2026-11-16。此文记录实际证据及后续施工要求；不将旧修复失败归咎于用户没有刷新。

## 本次已确认的事实

用户确认插件1.7.0，截图再次显示“正在应用龙门四小只”后报 `Cannot read properties of undefined (reading 'map')`。
本轮只读核对得到：

| 对象 | 实际结果 |
| --- | --- |
| 服务器剧情插件 | 1.7.0 |
| 酒馆助手 | 4.12.1 |
| 不带尾号的卡 `明日方舟·剧情完整版_插件版.png` | 1.7.0，构建 d891760122c0，绑定 v5_0 |
| v5_0 主世界书 | 2049条，key/keysecondary数组全部有效 |
| 服务器保存的 `active_character` | **明日方舟·剧情完整版_插件版1.png** |
| 该尾号1卡在补正前的版本 | **1.5.1**，构建 b7a62dc91ea9 |
| 该卡绑定的主世界书 | **v4_1**，2049条均缺少原生关键词数组 |
| 另两本历史坏书 | v4_2/v4_3，各2049条仍保留旧格式 |

因此“插件已经1.7.0”和“实际选中卡仍绑定旧坏书”可以同时成立。不能仅凭扩展页的版本号判断角色卡、脚本与主书都已更新。
`active_character` 是服务器保存的选择记录；它不等同于直接读取了浏览器当前JavaScript运行栈。本次没有取得页面错误栈，不能把这一证据层级混淆。

## 问题回顾

第一处真实缺陷是世界书格式：把卡内 CharacterBook 的 `keys/secondary_keys/enabled` 条目直接包装后写给原生世界书接口，缺少 `key/keysecondary/disable` 等转换。助手读取器RH直接调用关键词数组的 `.map()`，会因此崩溃；该缺陷已在1.6.2修正原生产物。

本次暴露的是部署目标漏检：旧部署脚本把目标头像写死为不带尾号的文件，核验也读取这个文件。服务器中实际保存选中的却是带尾号1的另一张卡。旧流程证明“某张1.7.0卡及其书有效”，没有证明“用户正在用的那张卡被更新”。

上次229项测试、165项成品检查证明编译产物和规则执行有效；临时书接口检查证明指定的新运行时可以读写。它们不能替代当前选中头像、绑定书及浏览器实际调用目标的核验。此前将上述检查直接概括为用户端已恢复，结论过强。

## 以后更新的必做顺序

1. 确定运行实例与数据用户，读取当前角色选择标识。优先核对浏览器真实 `avatar_url`；无浏览器条件时至少读取服务器保存的 `active_character`，明确标注证据来源。
2. 建立实际头像文件清单：**完整文件名（包括尾号）→卡版本→脚本构建/哈希→绑定世界书→书的实际字段格式**。不能只比较卡的显示名称，不能凭“插件版.png”猜目标。
3. 若实际头像与默认文件不同，使用实际头像名进行 `preserved_name` 导入。用户明确指定非当前头像时以该明确目标为准；选中的是无关角色则停止覆盖，定位本模块的真实目标，不得改无关卡。
4. 在实际目标上读取原聊天指针、收藏标记并备份。导入新卡后对**同一头像名**恢复并回读聊天指针；不以另一个头像目录下的聊天文件存在代替。
5. 验证实际目标卡的版本、脚本哈希和绑定书，读取它真正绑定的原生书，逐条检查关键词数组，再执行实际助手读取与开局服务。
6. 优先修补错误目标。已有v5_0世界书正确时，不为补正头像而重置该书，不重新初始化玩家的条目开关或剧情进度。
7. 用户刷新页面后，能做浏览器验收时核对实际头像/主书，并点击同一个失败开局一次。无页面验收条件时明确写“服务器目标及接口已核验，页面点击未核验”，不能笼统写“全部正常”。
8. 若实际新卡、新书仍出现同样文案，采集该次错误栈、实际书名、失败UID与字段类型，区分**读取器、写回序列化器和其他 `.map()`**。不要仅因文案相同就认定同根因；不要继续堆版本号或增加与失败路径无关的通过数。

## 验收必须包含的反例

- 默认头像是最新版，尾号1头像是旧版，当前选择尾号1：更新应命中尾号1。
- 插件最新版，但当前卡或绑定书旧：必须判定仍未完成用户更新。
- 两张卡显示名称相同、文件名不同：必须按头像标识区分。
- 当前选择为其他角色或无法确定目标：不得默默覆盖默认文件或无关卡。
- 指定卡有效，但其实际绑定书缺关键词数组：失败信号不能被另一本文字相同的新书通过所掩盖。
- 补正目标时保留原聊天/收藏，正确世界书字节不变；不能通过清空聊天或重置世界书制造成功。

## 本轮修正入口

- `work/repair_selected_card_1_7_0.py`：针对本轮版本的实际选中头像补正；只从stdin接收凭据，核对现有正确主书，保留目标聊天与收藏，不重写主书。
- `work/run_selected_card_repair.py`：会话级SSH执行入口，不把密码写入文档或脚本。
- `work/deploy_1_7_0/install_server.py`：已移除固定头像目标，按真实选择或明确target_avatar选择，增加本模块身份检查。
- 回执以 `work/publish_1_7_0/当前选中卡补正核验.json` 为准。旧部署回执仅代表当时核对的默认头像，不代表尾号1卡已更新。
