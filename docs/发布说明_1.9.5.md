# 1.9.5 维护及交付说明

运行时、插件版本、便携角色卡一起发布，数据沿用1.9.3，原文、摘要、层级与稳定ID不重编。线上实际卡原头像不改，只替换脚本、版本和显示名，聊天指针、世界书绑定、收藏保留。便携卡另含2049条未污染发布基线；不要重新导入世界书来更新已有玩家状态。

## 剧情请求

`generate` 本来即使用当前预设，本次调整请求组织方式。开场将当前指导和当前段资料放入 `user_input`，系统侧保留规则与状态索引。取消、超时、成功、异常都恢复普通回复的资料注入；切聊天后不恢复旧聊天提示。请求不保存为玩家消息。不得改成 `generateRaw`、复制未来章节、把对白视作玩家指令或无上限重试。

日志曾出现供应商 `NON_ASSIST_SEEKING_QUERY_IGNORED`，明确请求的短测可成功；这不能证明全部剧情失败只有同一原因。使用当前预设的完整剧情演出仍需实际回复核验。

## 管理员部署

确认实际选中头像属于本模块、插件目录干净，记录部署前提交。拉取本版后暂停酒馆服务，执行：

```sh
python3 /root/SillyTavern/data/default-user/extensions/mmddj/maintenance/install_1_9_5.py /root/SillyTavern
```

安装器检查精确旧哈希，拒绝未知核心版本，旧文件和回执保存到 `/root/.ark-story-deploy-backup/v1.9.5-时间/`；失败恢复已替换文件。启动原服务后核对健康状态、实际卡脚本哈希、HTTP依赖资源。不要重置设置或重新生成剧情数据。

保存版本协议覆盖单聊、群聊、角色改名批量更新及新建分支。旧浏览器缺少读取版本会被拒绝保存，需要刷新。第三方直接保存接口同样需要适配。明确强制覆盖前自动备份原文件。

## 回滚

暂停服务，按备份 `receipt.json` 的 `original_files` 恢复同名文件；原本不存在的 `ark-chat-revisions.js` 单独删除，恢复备份卡。插件切回部署前提交，再启动并刷新。禁止递归删除用户数据目录。回滚恢复代码及卡片，不回滚玩家聊天、设置或世界书。
