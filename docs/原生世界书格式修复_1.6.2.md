# 原生世界书格式修复 · 1.6.2

## 已确认根因

1.6.1 的服务器部署脚本将卡内 CharacterBook 条目直接复制给原生世界书接口。
服务器上 2049 条条目都有 keys/secondary_keys，却没有原生 key/keysecondary。
已安装 TavernHelper 4.12.1 的 RH 读取器直接执行 e.key.map 和 e.keysecondary.map，因此开局应用时崩溃。
在原部署产物上使用该实际读取函数，精确复现用户截图的 undefined.map 错误。
上版正文和版本号核对未检出字段格式错误，不能作为开局功能通过的依据。

## 修复

- scripts/native_worldbook.cjs 按实际 SillyTavern 1.19 convertCharacterBook 契约转换字段，并校验 UID/关键词数组/位置/顺序/角色/禁用值。
- 原始 CharacterBook 继续保留在 PNG 中；其 enabled 与显式 disable 统一，正确表达默认关闭的指导与档案条目。
- 插件 data/base_worldbook.json 是原生 UID 字典，服务器安装只导入该文件，禁止再次把卡内 entries 数组直接摊平复制。
- 原生文件单独记录 SHA-256、字节数及 schema；部署前和落盘后均校验。
- 同步 v4_4 世界书与配套卡 1.6.2。剧情正文、UID、路线、存档 ID 均保持。

## 验证

- 原脚本及原格式执行助手读取和开局服务均精确报 undefined.map；修正后读取 2049 条通过。
- 使用卡内实际编译开局服务、开局表和名称规范化函数，在隔离副本中执行全部 61 个开局（含龙门四小只），核对各目标条目的启用与关闭值；不改玩家实际开局。
- 219 项测试、159 项成品检查通过。未调用付费模型；隔离服务测试不等同于真人页面点击。
- 剧情数据与 1.6.0/1.6.1 逐字节一致，SHA-256 4c301a5dd443bcf6ce4369639cc6229d1f53174b7a0a3d701430d07745b70449。

## 后续施工防回归

构建入口须持续产出 data/base_worldbook.json；安装脚本不得再把 embedded CharacterBook 的 entries 当成原生条目。
修改部署流程后，必须对实际落盘条目运行已安装助手的 RH 函数，以及完整开局服务回归，不能只验证正文和条目数。
脚本位于本地工程；发布物中附完整原生世界书，用户无需另行手工转换。
远程更新继续沿用原仓库，导入新卡后恢复原聊天指针，不读取聊天正文。
