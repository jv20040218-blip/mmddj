## 2. 已确认且仍有效的产品要求

### 2.1 交付与操作

- 保留原插件仓库及main更新来源。用户通过原扩展更新，不手工覆盖目录、不卸载重装。
- 功能或运行时更新交付配套新PNG，正常情况下包含基础世界书和运行脚本；大体积剧情原文留在插件。
- 用户使用包只有三项：`角色卡.png`、`插件链接.txt`、`更新交付协议.md`。源码、台账、报告放工程与仓库，不再往桌面堆叠不同修复版文件夹。
- 同源剧情插件保留一份；这不授权删除所有旧头像、历史世界书或聊天。
- 修改指导或部署说明而运行时未变，可以保持运行时版本，记录指导版本和提交；不得为文档更新伪造运行时新版或重写不可变标签。
- 卡显示名、实际头像文件名、卡版本、内嵌ARK_UI外壳版本、插件版本、构建ID、数据版本、世界书名是不同字段。尤其`ARK_UI v6.x`不能代替产品卡版本，尾号头像不能忽略。

### 2.2 目录与剧情

- 顶层只显示：**主线、支线、其他**。
- 主线为“主线 → 1–8／9–14／15–17 → 每章”；第一块包含序章及对应各章。每层使用展开标题，不用一个下拉选择框代替所有章节。
- 塔露拉雪原个人记忆线置于1–8其余主线前，第八章不再强制重复插播已体验回忆。
- 支线为“支线 → 国家 → 每章”。无国家归属的专题、联动、独立补充放其他。归属从实际素材路径重建，不能仅修改可见标题。
- 当前14份主线、39份支线是已核验快照，不是永久数量上限。新增素材须接入并更新报告，不能为了维持39而丢文件。
- 一章可拆成连续A线、B线，交汇事实去重，必要跨线背景输入保留；不因场景相同删除不同人物视角。
- 先完整预览、再确认进入。玩家可自由选幕/段、保存退出和续玩；AI判断不能成为唯一推进途径。
- 手动跳读不补记完成。正常“继续下一篇”要求本线末段确实完成，和自由进入别的幕是两个入口。
- 完整对白、动作、旁白保存在原文库；梗概、指导和链接不能冒充已补齐原文。

### 2.3 时间、人物与状态栏

- 时间按**剧情内时间**推进，不按现实等待时间强制改变人物。当前主目录优先章节与国家，年代列表为辅助，不能退回早期“全局严格按日期”的旧方案。
- 有依据的日期保持原精度，无依据显示“暂无”；未定年在辅助年代视图单列下方。不能把月初/年初排序锚点显示成官方精确日期。
- 已到时间或玩家在剧情中实际达成的事件可按规则触发变化；未核实日期及转折不得冒称官方已证实。
- 每次进入、正常推进、切幕、切线、退出回忆和恢复聊天，重新判断当前场景中的人物身份、同名后缀及来源档案。
- **切换必须实际关闭旧状态条目，打开对应目标条目，写入世界书并回读。** 生成时临时投影可辅助隔离，但不能替代真实复选状态。
- 开局性别等玩家选择不由默认年代擅自覆盖。控制解除、能力获得、组织加入、外形/职业和表情差分分别建模，不混成一次切条目。
- 状态栏给出时间、当前线/段、情况、纪事、下一步、人物及资料后缀；同一作用域没有新事件则重复上一条。
- 回复正文底端继续显示可见摘要。结构化`ark_turn`是程序结果，不要求模型暴露内部思维过程；由程序检验ID、revision和推进确认。
- 剧情原文作为事实及因果参考，不要求逐字复刻；先回应玩家真实输入、结合聊天中已发生的事实，不代玩家决定、不强制重播。资料提示使用system，不伪装成较新的user发言；当前幕范围及完成条件保留。
- 每段台词独立闭合引号，不使用连续多段只在末段闭合的格式。1.8.1对明确中文台词行提供生成结束后的补号；不改词句、代码、控制包和其他消息页，不额外生成；格式重绘不得重复结算。不能据此宣称所有模型的叙事质量已验证。
- 状态栏不得覆盖发言栏或顶部工具栏；最新定位为聊天区顶部、主工具栏下方。折叠、低屏高和触控交互仍需按真实页面检查。
- 删除旧“拦截记录／STANDBY”小窗；原控制台入口直接打开自适应全屏界面，关闭按钮和Escape只关闭界面，不关闭应用或退出剧情。最新1.8.2以单一顶栏/伸缩内容/底栏结构替换旧FULL/MINI分支，禁止用一个通用grid规则把旧两套区域一并展开。
- 剧情顶部有“剧情目录、当前剧情、剧情摘要、角色立绘、历史记录”五个入口。摘要与立绘各为独立页面，当前剧情提供直达和返回入口，不再只放在底部折叠栏里。选线后可用，查看资料不改变游标；摘要按实际幕序完整展示，禁止截成前12幕或首尾样本。
- 原重置按钮覆盖全部已编入基线的条目开关及触发类型，先退出活动剧情并撤除当前注入，保留体验进度。它不等于还原被修改的正文、找回被删除的条目或清空聊天。

## 3. 证据等级与允许写出的结论

| 证据 | 能证明 | 不能替代 |
| --- | --- | --- |
| E1 读取源码/字段/文件 | 内容、路径、格式、候选原因真实存在 | 缺陷已复现或用户端恢复 |
| E2 原错误复现与回归 | 指定输入在旧代码失败、修复后通过 | 不同目标、不同宿主的结果 |
| E3 最终PNG/数据/原生书检查 | 产物相互配套、哈希和正文可比对 | 安装到用户实际选择的头像 |
| E4 内存宿主/DOM/全量规则遍历 | 大量线路状态与规则执行一致 | 正确的官方考据、真实页面几何、真人玩通 |
| E5 服务器API/真实落盘 | 指定目标已保存、可读写、元数据与文件一致 | 浏览器当前内存正在使用该目标 |
| E6 实际交付运行时＋临时书真实API | 真实读写边界上指定案例/重置可用 | 用户原失败按钮已点击成功 |
| E7 浏览器实际头像、书与原失败动作 | 该时刻该页面的交互结果 | 所有章和所有供应商永久正常 |
| E8 经授权模型演出 | 指定模型、上下文、次数的生成及状态提交 | 每一段对白均经人工考据 |

当前1.7.0全量基线为229项测试、165项成品检查、9885次场景访问；另有6项部署目标选择测试。样式版相关回归单独记录，不能把不同批次数字拼成一个未执行的“总通过”。1028万余项开关断言验证执行一致性，不是1028万次真实网络请求，也不是全部官方剧情语义核实。

1.8.0重新执行的全量回归为234项、成品检查165项；本次新增真实19幕及全849条线摘要幕序核对，完整测试未跳过用例。仍未取得真实浏览器布局验收证据。

1.8.1增加上下文叙事及用户引号样例回归，完整重跑242项测试与165项成品检查，均通过、无跳过，无模型调用。用户曾要求“先等等”，随后明确“允许更新，我先看看效果”，已完成本次部署；具体服务器版本及保留项见当前快照和部署回执。发布状态与部署状态仍须分别核对。

## 4. 遇到复发先做什么

### 4.1 `.map()`、无主世界书或开局失败

```mermaid
flowchart LR
  A[实际运行实例] --> B[实际头像完整文件名]
  B --> C[卡版本与脚本构建哈希]
  C --> D[实际绑定世界书]
  D --> E[UID与原生字段格式]
  E --> F[本次错误栈和失败入口]
```

1. 固定用户看到的文案、原失败动作、当前时间与本次版本，不先升级、不先清聊天、不先归因缓存。
2. 确认实际服务根目录和数据用户；同服务器可能同时存在运行副本与闲置clone。
3. 获取浏览器真实`avatar_url`；缺浏览器条件时读取服务器保存的`active_character`，明确写是保存记录。保持尾号和完整文件名。
4. 对这张卡读取产品版本、卡内脚本构建与SHA、实际书名；扩展页1.7.0不能证明卡也是1.7.0。
5. 检查真正绑定的书，不用另一本新书通过替代。原生`key`和`keysecondary`必须为数组，还要核对位置、禁用语义和其他必要字段。
6. 收集本次栈，区分读取器`RH`、写回序列化器和其他代码的`.map()`。文案相同不等于根因相同。
7. 若是实际头像漏更新，使用其完整文件名补正，保留它的聊天与收藏；正确书不重置。
8. 若是格式错误，按真实宿主契约转换；先备份该书及关联，再在授权范围修补，禁止只把字段补空来压制异常。
9. 修复后回读同一头像及绑定，能做页面验证时再点原失败开局一次；未做则保留待核验。

已确认的两条独立路径：第一次原生产物格式错误；第二次安装器核验默认头像，而服务器保存选中的尾号1卡仍为1.5.1、绑定旧坏书。它们都足以触发同类文案。详见台账B048、B051及[1.7.0复发指导](更新指导_1.7.0开局map错误复发.md)。

### 4.2 其他症状分流

| 症状 | 优先检查 | 先不要做 |
| --- | --- | --- |
| `[开局占位符]`或控制台完全不出现 | 卡脚本是否启动、静态导入/CDN、实例与错误日志 | 直接判定供应商问题 |
| 回复取消、空回或502 | 原生发送与预检调用、供应商结果、实际生成文本 | 无限自动重发、换一堆模型 |
| 没有完整正文或剧情跑偏 | 命中数据URL、原文库、当前段注入、指导是否泄露未来 | 只改提示词让模型补写原文 |
| 国家或章节缺项 | 当前素材清单、source_relative_path、目录成员和迁移表 | 重复添加正文、按篇目数强行补齐 |
| 角色状态不对 | 本名/代号、场景锚点、来源后缀、实际开关与回读 | 只告诉AI“你现在是某状态” |
| 进度卡住 | 当前节点/段/完成判据、玩家停留指令、busy与超时 | 把所有跳过内容标成完成 |
| 世界书重置后仍按旧剧情回答 | 活动路线是否退出、固定注入是否撤除、全UID覆盖 | 清空聊天或永久禁用剧情模块 |
| 状态栏遮挡发言栏 | 宿主挂载点、fixed top/bottom、主题工具栏高度及z-index | 只降透明度而保留遮挡位置 |

## 5. 数据、路径、身份及格式契约

### 5.1 工程、发布与运行场所

| 场所 | 当前项目位置/内容 | 用途 |
| --- | --- | --- |
| 可重建工程 | 工作区`work/plugin_hierarchy/工程/` | 改src/scripts/tests及工作数据 |
| 发布工作副本 | `work/publish_1_6/repo/`，名字是历史沿用 | 安装文件在仓库根，向正式GitHub推送 |
| 健康镜像 | `work/publish_1_5/remote_repo.git` | 已验证的bundle来源；使用前确认引用 |
| 交付输出 | `work/delivery_<版本>/` | cards、extension、worldbook、报告、指导 |
| 运行安装目录 | 由实际端口进程/服务确认的SillyTavern及用户extensions | 不拿本机工作目录代替实际服务 |
| 公开插件根 | manifest/index/style/data/cards/tools/docs | 非完整工程，不能默认在这里跑全部工程构建 |

服务器历史运行实例为`/root/SillyTavern`、default-user、用户扩展mmddj；同机器另有闲置clone。以上是历史坐标，下一次有授权部署时先确认，不能把PID或绝对位置当永远不变。

素材根必须同时满足主线、支线和清单中的参考文件。用户新给的`Desktop/支线`可以成为支线权威，但不能直接当成包含全部参考文件的总素材根。目录迁移先登记，不直接移动后全库重编。

### 5.2 稳定ID与原文

- `source_id/story_id/route_id/scene_id/世界书UID`均作为存档接口。标题或路径变动不自动换身份。
- 移文件前登记`data/source_migrations.json`，包含新旧路径、稳定ID及正文哈希，再运行迁移及审计脚本。
- 一次归属迁移要同步导航入口、corpus.sources/file_manifest/per_source、节点/段来源定位、route_guides和sources注册表。
- `work/runtime_v2.json`是导入profiles前的工作输入；不要把已经导入人物档案的成品`story_runtime.json`直接灌回再重复导入。
- 补采先保存原文件、原UID、字符区间、来源URL、材料精度。只修改归属时正文哈希应相同；修改原文时明确记录差异，不能继续声称逐字节未变。
- 新增人物后缀须有身份及时期依据；相同身份相同正文可复用，不能给同名的不同身份强合并。

### 5.3 两种世界书格式

| 概念 | 卡内CharacterBook | 原生SillyTavern书/接口落盘 |
| --- | --- | --- |
| 条目容器 | entries数组 | 按UID的entries对象 |
| 身份 | id（或兼容uid） | uid及对应字典键 |
| 主关键词 | keys | key数组 |
| 次关键词 | secondary_keys | keysecondary数组 |
| 开关 | enabled | disable，语义取反 |
| 顺序 | insertion_order | order |
| 位置 | position及extensions.position | 原生数值position |
| 扫描/递归/概率 | 多在extensions中 | scanDepth、preventRecursion、probability等原生字段 |

统一使用`native_worldbook.cjs`转换和校验。卡内`enabled`与显式`disable`必须一致；不能只补两个空数组，也不能只把entries变字典。

已核对的宿主为SillyTavern1.19.0与TavernHelper4.12.1。该助手位置映射为0角色定义前、1后、2作者注释前、3后、4深度、5示例前、6示例后、7outlet；role为0 system、1 user、2 assistant。升级宿主后重读实际契约，不能用另一份旧枚举猜测。

插件中的`data/base_worldbook.json`是原生部署产物，`data/story_runtime.json`是剧情数据；独立CharacterBook导出版不是直接写给原生接口的替代品。实际用户书的开关可以因剧情而不同于发布基线，不能据此判成正文损坏。

### 5.4 无书内容变更的样式补丁

若只改样式/定位，沿用完全相同的已验证书和剧情库，避免将用户的开局状态重置。1.7.1是此分支：脚本差异限定定位及构建标识，书和数据逐字节保持。

工程支持显式`ARK_REUSE_WORLD_CARD`复用已核对的上版书；生成器会拒绝数据版本或条目正文不一致。它不是绕过世界书版本管理的开关。只要书内容或UID语义改变，就按配套内容更新流程处理，不能强行复用旧书。

## 6. 分支施工步骤

| 工作包 | 必需动作 | 通过条件 |
| --- | --- | --- |
| 仅文档 | 更新台账/模板，生成总指导，查链接、版本与事实等级 | 不改运行时、不调用模型，不把写入文档称为软件修复 |
| 目录/归属 | 核对当前素材、迁移登记、重建成员、保存旧ID | 新旧入口能对应，无漏收/重复正文，旧存档可识别 |
| 新篇/补原文 | 来源与区间、人物线/交汇、分段、当段注入、人物映射 | 原文逐段可重建，当前提示命中正确段，无未来对白泄露 |
| 人物/时间 | 身份别名、证据和后缀、节点与日期作用域、实际书开关 | 目标开启、同人旧态关闭、回读一致、退出恢复，未知保守标注 |
| 开局/书格式 | 真实目标与错误栈、原生转换、读入和写回契约 | 对同一失败目标复现/修复，缺书不假成功 |
| UI样式 | 命中真实宿主文档/挂载点，保留输入与导航交互 | 定位正确，输入和菜单可用，窄屏无遮挡；缺真实页面证据就注明 |
| 部署补正 | 实际头像、聊天/收藏、脚本与书哈希；正确书保持 | 原头像更新而非新增替身卡，关联恢复，不清进度 |

新增模块同步构建器的模块表，至少检查`build_plugin.cjs`、`build_card.cjs`、`scripts_src/build_bundle.js`相关路径；只改src但最终卡未包含新模块不算完成。原控制台补丁须检查唯一锚点，命中零次或多次都失败，不能静默跳过。

## 8. 发布与服务器更新

### 8.1 原仓库发布

1. 确定代码/数据/卡/书是否变更，选择正确版本及内容更新或样式复用分支。
2. 检查本地工作副本是否有别人的未提交改动；保留并整合。发布工作副本的origin可能指向本地镜像，因此正式核验应明确读取GitHub正式仓库，不把镜像最新当外网已发布。
3. 卡、独立脚本、原生书、数据与清单一致，最终PNG能解码，图像块和必要元数据兼容性有记录。
4. 运行与变更匹配的验证，记录对象/输入/结果与未测范围。报告里的版本与计数取实际产物，不硬填成功数字。
5. 正常推送原main。运行时更新建立新标签及带版本PNG，标签不重写；文档更新记录自己的提交。
6. 从远程核对主分支/标签、正式卡实际下载哈希、数据和原生书清单。只有本地提交不算链接已更新。
7. 最终用户使用包只同步三项，历史工程与回执留工作区。没有仓库权限时一次说明具体缺项，不虚构链接或声称发布。

### 8.2 有授权时部署

1. 确认当前授权覆盖的动作和实例；同一修复已授权的步骤不反复询问。若此前明确仅限某次且本次确实扩大范围，先做出可审阅结果，再说明具体限制来源申请最后一步批准。
2. 从实际服务确认根目录、用户、同源插件、origin和当前提交。不要更新闲置clone，不硬编码旧PID。
3. **确定实际头像**：浏览器avatar优先；保存的active_character作为有标注的替代证据。核对尾号、模块身份和用户明确目标，不能默认固定卡名。
4. 对该头像保存最近聊天与收藏，备份卡。只核对聊天文件存在，不为部署读取聊天正文。
5. 外网慢时从健康镜像制作针对实际基准提交的bundle；检查前置提交与导出引用，SFTP上传后核对SHA，不按文件大小盲复用。
6. 原目录fetch实际导出引用并`merge --ff-only`，保留origin和干净工作区。禁止为掩盖冲突覆盖无关用户修改。
7. 内容更新导入正确原生书；样式或目标补正不重写已正确的用户书。新书名、兼容UID和用户开局状态如何衔接必须明确，不能顺带恢复默认开关。
8. 使用认证会话、Cookie和CSRF调用原生角色导入，`preserved_name`为真实目标完整头像名，不以另一个同名显示卡代替。
9. 导入后用角色API恢复并回读真实聊天指针/收藏。不能只写某一PNG文本块就认定成功。
10. 核对同一目标卡版本、构建/脚本SHA、真实绑定书与原生字段，再检查HTTP实际插件/数据、单份安装和启用状态。
11. 用已安装助手真实读取函数测试对应数据。需要真实写入验证时用临时未绑定书执行交付卡运行时、读回开关、退出恢复及完整重置，结束删除临时书。该路径不等同浏览器点击。
12. 可用时刷新并实点原失败入口；不可用时明确记录待核验。清理本次传输临时文件、保存不含凭据的回执，更新三项使用包。

提供服务器地址/密码的一次授权不是永久扩权。凭据只由当前授权会话或临时进程环境提供，不进入仓库、PNG、台账、报告或教程；本指导不包含真实服务器账密/API密钥。

## 10. 回退、保留与不可误用的历史资料

- 回退必须是一组相互匹配且格式健康的插件/卡/书/数据，不只是指向某个旧标签。
- 旧v4_1/v4_2/v4_3书在上次审计中各有2049条缺关键词数组；历史教程写“旧书可留回退”不等于这些副本健康。
- 错误选中卡1.5.1的备份是事故现场证据，不自动成为可用回退方案。先核对书格式和对应聊天关联。
- 原卡、旧聊天、正文与稳定ID默认保留；用户此前某次清理桌面的授权不延伸为以后自动删文件。
- 清同源重复插件时核对真实绝对目录、origin与新实例成功证据；不遍历后交给另一个shell拼接删除。
- Git原桌面库有损坏对象的历史，优先健康副本。发布提交与内容提交可能不同，按清单说明及祖先关系核验，不覆盖标签来凑相等。
- 文件路径和版本写法经常过期。`work/publish_1_6/repo`和`publish_1_5/remote_repo.git`只是沿用的目录名，不能据此判断产品版本。
- 世界书操作若失败要向上传递，不能弹失败后仍切开局、清提交记录或给成功回执。

## 16. 如何维护这份总指导

- **问题事实、状态、版本和证据的权威数据是`问题与修复台账.json`。** 当前文件由`总指导模板.md`和该JSON生成，不手工分别维护两份问题事实。

- 状态变更要附证据；“写了指导”“加了防护”“发了版本”不自动把待核验改成已修复。
