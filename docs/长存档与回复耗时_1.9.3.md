# 长存档与回复耗时 1.9.3

由 1.9.1 升级时，原始剧情数据的 SHA-256 仍为 09caf7b52651d38a1c39f5593529f96b78c21132cd23a9003c26505e79f70b4a。角色卡沿用原存档格式，可用之前的卡读取更新后的剧情进度。发布包同时提供 16,753,082 字节的压缩数据以及完整 JSON 回退路径。本地浏览器缓存仅保存公开剧情资料。浏览器清理站点数据后会重新下载。

首次打开会解压并解析整库。隔离 Chromium 中连续两次独立打开，合计一次压缩包传输。旧格式模拟档为 10,707,251 字节，含 500 条历史快照。新旧版本各追加五轮、重开、回看最早一条、回退并分支，对照所得状态一致。宿主仍可能在写入聊天变量和保存时处理整档。

发言前仍核对实际世界书，开关需要变动时执行写入与回读，预演复用待完成的同步。以雪原线十九幕对照，每次模型输入去重 1,230 至 1,346 个字符。原文、角色信息、控制指令与推进边界依旧可用。

要定位线上等待，在浏览器控制台筛选「回复耗时」。记录按毫秒显示剧情发送准备、准备后至首段、首段至结束及生成事件总时长。非流式回复可能没有首段记录。这些时间包括酒馆和其他插件在相应阶段的工作。生成事件前的排队或预演需要结合浏览器请求时序判断。

本地通过 159 项回归和针对压缩缓存、长档、世界书外部改动与剧情提示的专项核验。实际模型响应时间取决于使用中的聊天、预设及服务。修复前后应在相同条件下比较。
