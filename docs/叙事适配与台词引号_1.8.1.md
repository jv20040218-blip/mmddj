# 1.8.1：结合聊天演出与每段台词引号

2026-11-17，用户反馈剧情经常照搬原文、忽视上下文，且台词缺少部分闭引号。随后提供阿丽娜与塔露拉谈论风景画的具体回复，其中连续数段以“开头，最后才闭合。用户希望每段台词独立成对。

## 实现

- 删除“保留原文标点、段落和发生顺序”的复刻要求，原文改作事件、人物动机和因果参考。明确先回应玩家真实输入，结合已经发生的聊天事实，允许重写台词与动作，不代替玩家作决定、不重播既有内容。
- 剧情材料提示从user改为system，避免伪装成较新的玩家发言。取消200字建议上限，保留可见状态摘要及结构化结果包，当前幕与未来知识边界不变。
- 正常推进以完成条件是否实际达成为准，不以复述原句为准；玩家阻拦、提问、观察时保留现场，不强行恢复原文或确认未发生事件。
- 旧世界书中的专用运行规则，在当前生成投影中替换为新规则；实际世界书正文与人物复选状态不因此改写。原剧情库、UID及v5_0世界书沿用，现有存档无需迁移。
- 明确每段台词独立闭合，即使同一人物连续说话，也不采用仅最后一段闭合的写法；JSON仍保留英文双引号。
- 增加确定性补号函数：仅对以中文开引号开始，或由冒号/逗号引出的明确台词行，补缺失的中文闭引号；不改原词句。代码块、内联代码所在行、控制包与其他引号样式保持原样，重复执行不重复补号。
- 开场在写入前处理；普通聊天在生成结束后仅更新本次新AI回复的当前消息页。停止、预检、静默生成未新增楼层、失败重生成和切聊天不借此批量改历史；其他消息页不动。更新显示引发的重绘不能重复提交剧情控制包。写回失败只记录提示，不取消回复、不额外生成。

## 实际样例

用户提供：

```text
“这个笔触……这不是附近的画工画的。
```

处理结果：

```text
“这个笔触……这不是附近的画工画的。”
```

同一段阿丽娜连续讲话样例共补3个闭引号，其余原文不变。已有完整引号、嵌套引述及英文台词，经过控制包解析与显示正则后均保持原样。没有发现卡内隐藏控制块的正则在删除正文引号；这次修复针对已提供的跨段闭合格式，不推断所有丢引号都是同一原因。

## 验证与限制

8项针对性回归覆盖系统资料角色、上下文演出规则、开场、旧规则投影、标点保留、实际样例、当前消息页幂等更新、停止/预检/写回失败。最终测试数字以本版release.json与最终回执为准。

未调用付费模型，未实测供应商的自由演出效果；规则变更和确定性补号已离线验证，不能将其写成“所有模型从此绝不照搬”。原文库仍保留完整素材，不用删对白换取表面上的自由。

`setChatMessages`按[酒馆助手官方类型定义](https://github.com/N0VI028/JS-Slash-Runner/blob/main/%40types/function/chat_message.d.ts)使用`message_id/message`与`refresh:'affected'`；其更新会触发渲染事件，因此适配器提前标记格式版本，防止同一控制包再次结算。该接口契约核对不等于在用户服务器执行过真实写回。
